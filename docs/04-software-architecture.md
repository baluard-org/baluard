# IDtty: Software Architecture

> Monorepo software architecture for the Rust Core Space Manager.
> Covers: monorepo structure, Single-String Protobuf Gateway (planned), Unix Domain Sockets IPC, Tauri v2 tray integration, UniFFI mobile bindings (planned), Kotlin Multiplatform JIT mobile sync, and Mock Engine.

## 2. Unification: Single-String Protobuf Gateway (Planned)

**Current state**: Protobuf gateway fully wired. CLI has dual-mode (daemon-first + `--direct` fallback). Daemon has 16 routes (vault, sync, devices). Tauri desktop scaffolded via `tauri init` with daemon proxy command.

**Target state**: All application tiers (Tauri Webview, CLI, KMP Mobile, Browser Extension) communicate with idtty-core through a serialized Single-String Protocol Buffer Gateway:

```rust
// crates/idtty-daemon/src/handler.rs (target)
pub async fn handle_request(action: &str, payload: &[u8]) -> Result<Vec<u8>, IdttyError> {
    // 1. Deserialize payload to the corresponding Protobuf schema
    // 2. Route action to the appropriate idtty-core module
    // 3. Serialize response back to Protobuf
    // 4. Return bytes
}
```

### Mobile Direct Binding (UniFFI, Planned)

On mobile, the Protobuf gateway is bypassed. UniFFI generates direct Kotlin/Swift function calls into idtty-core:

```kotlin
// Planned: Auto-generated by UniFFI from #[uniffi::export]
val entries = IdttyCore.listEntries(spaceId)
val decrypted = IdttyCore.decryptEntry(entryId, biometricKey)
```

### Mock Engine Support (Planned)
For front-end contributors, both the Tauri Desktop UI and the KMP Mobile UI will support a `MOCK_BACKEND=true` build flag.
- When enabled, the UI bypasses native compilation entirely.
- The UI feeds hardcoded Protobuf strings directly to frontend components.

## 3. Platform Tier Architecture

### 3.1 Desktop Tier (B2C/B2B)

**Current state**: CLI dual-mode (daemon-first via socket + `--direct` fallback). Daemon fully implemented with vault state, sync, devices. Tauri desktop scaffolded with daemon proxy and system tray.

**Implemented**:
- **Rust Daemon (`idtty-daemon`)**: Started by the Tauri tray wrapper on boot. Unlocks the vault directly in `zeroize`-protected memory. Opens a platform-aware Unix domain socket (Linux: `$XDG_RUNTIME_DIR/idtty.sock`, macOS: `~/Library/Application Support/idtty/idtty.sock`) with 0600 permissions (set via umask before bind to avoid TOCTOU race). Listens for length-delimited Protobuf requests via tokio async I/O. SO_PEERCRED peer UID verification on Linux.
- **CLI (`idtty-cli`)**: Dual-mode binary. Default: compiles flags into Protobuf, transmits over socket, prints response. `--direct` fallback links idtty-core in-process. `--socket <path>` for custom daemon path.
- **Tauri v2 UI**: SolidJS/Tailwind v4 webview scaffolded via `tauri init`. `daemon_request` Tauri command proxies to daemon via Protobuf over Unix socket. System tray with Show/Quit menu. Login screen + vault view with cipher CRUD. Dark theme. Rust edition 2024.

### 3.2 Mobile Tier (B2C)

**Current state**: Placeholder scaffold only. No UniFFI annotations applied.

**Target architecture**:
- **KMP UI**: The application interface written in Compose Multiplatform (Kotlin Multiplatform) for shared Android/iOS screens.
- **UniFFI Bindings**: idtty-core's public API will be annotated with `#[uniffi::export]` proc-macros. At build time, UniFFI generates:
  - **Kotlin** bindings compiled into the Android module
  - **Swift** bindings compiled into an xcframework for iOS
- **No intermediate language**: Rust calls go directly to native code. No cgo, no JNI boilerplate, no gomobile.
- **Just-In-Time (JIT) Sync Hook**:
  1. When a mobile browser autofill action triggers, the OS calls the app's native autofill adapter.
  2. The JIT hook calls `sync::fetch_delta()` via UniFFI to check for remote changes.
  3. If a delta exists, idtty-core pulls and decrypts updated buckets.
  4. The OS prompts for biometrics (FaceID/Fingerprint) and autofills the credential.

## 4. Platform Keyring & Escrow Bootstrapping

- **OAuth PAT**: The token is never stored in Git. It will be escrowed securely in the host OS Keyring (Keychain on macOS/iOS, Secret Service on Linux, DPAPI on Windows, Android Keystore).
- **Device Digital Identity**: User's asymmetric private key is encrypted using KEK (derived from Master Password via Argon2id) and committed to the repository at `metadata/identity.enc`.
- **Enrollment Flow**: A user signing in on a new device clones the Space via OAuth, inputs their Master Password to decrypt `metadata/identity.enc`, extracts their private key, and writes it to the new device's local hardware enclave.

## 5. Security Architecture

- **Single crypto implementation**: All cryptographic operations live in `idtty-core/src/crypto/`. No duplicate implementations across languages.
- **FFI security boundary (planned)**: UniFFI's serialization approach provides a clean memory boundary. Rust heap allocations for secrets never share pointers with foreign code.
- **Socket permissions**: Socket born with 0600 via `umask(0177)` before `bind()` (no TOCTOU race between bind and chmod).
- **Graceful shutdown**: Daemon handles both SIGINT and SIGTERM for clean socket removal and vault zeroization.
- **Zeroize**: All passwords zeroized server-side (handler) and client-side (CLI unlock, Tauri proxy). `zeroize` crate with `derive` feature for guaranteed memory scrubbing via `write_volatile` + `compiler_fence`.
