- [B2] [crates/baluard-core] CTAP2/FIDO2 X.509 attestation parser omits the inner `OCTET STRING` (`0x04 0x10`) unwrap for `id-fido-gen-ce-aaguid` and rejects empty `basicConstraints` sequences (`crates/baluard-core/src/hwkey/attest.rs:237-265`, test fixtures at `attest.rs:810-820,852-859`). Per RFC 5280 Section 4.1.2.9 and W3C WebAuthn Section 8.2.1.1, an X.509 extension `extnValue` is an `OCTET STRING` encapsulating the DER-encoded extension value `AAGUID ::= OCTET STRING (SIZE(16))`, so `value_body` on real FIDO2 hardware keys (including YubiKey 5 and Security Key series) is 18 bytes (`04 10 <16-byte AAGUID>`). `attest.rs:264` converts `value_body` directly into `[u8; 16]` without unwrapping the inner `0x04` TLV, causing `parse_cert` to return `None`, `verify_with_pins` to return `AttestationVerdict::Invalid`, and `FidoStore::create_binding` (`crates/baluard-core/src/hwkey/fido.rs:190-195`) to reject enrollment on compliant hardware authenticators that carry the extension. In the same parser (`attest.rs:237-249`), `OID_BASIC_CONSTRAINTS` executes `let first = tlv(bc.body)?;` unconditionally, rejecting standard DER `CA:FALSE` (`30 00` empty `SEQUENCE`, where `cA BOOLEAN DEFAULT FALSE` is omitted per ITU-T X.690 Section 11.5).

- [B2 FIXED 2026-10-31, wave 1] parse_cert now unwraps the inner OCTET STRING and also tolerates the legacy single-wrap body (both shapes stay equality-bound to attested.aaguid, so nothing can be promoted), and basicConstraints accepts the empty SEQUENCE as explicit cA=false. The fixture builder emitted the single-wrap shape matching the broken parser; it now emits the spec wire shape, which is the honest red: a_fully_bound_attestation_verifies failed Invalid until the parser fix landed. Regressions pin both AAGUID shapes at parse_cert level plus the empty-SEQUENCE CA case (attest 26 passed).
